## Rootless 标识

rootless 首页标题旁增加不可点击的 `Rootless` 药丸标签，使用主题容器色与文字色。
两分支共享标题实现，通过明确的 `rootless_build` 资源区分；不依赖设备是否获得 root 来决定标识。
普通版资源值为 false，rootless 为 true。标题可省略，标签保持单行。
两 APK 均通过 assembleDebug/lintDebug，真机分别确认标签出现和缺席，截图检查了实际布局。

## 采集方法与范围

- 在 ADB 下确认 `su` 返回 uid 0；只读采样两个目标及项目测试应用的 `/proc/<pid>/maps`、状态、fd 链接、task comm 与相关 mountinfo。
- 冷启动两个目标时以短间隔连续采集 maps；未附加调试器、修改目标 APK、内存或退出逻辑。
- 只读复制 LSPosed 配置及 WAL 到被忽略的本地目录，SQLite quick_check 为 ok；仅查询两个目标和测试应用的模块作用域。
  没有修改其他模块配置。经 su 传输二进制使用 Base64，避免终端换行转换损坏数据库快照。
- 原始进程快照、配置副本、日志、截图及测试结果只存于 `.tools/runtime-device`，不加入源码或发布资产。

root 从外部观察到一条映射，不代表已证明目标恰好使用该入口检测；以下分别列出进程观察与应用内阳性控制。

## 确认的原生层缺口

| 观察 | 本轮证据 | 能得出的结论 |
| --- | --- | --- |
| 模块 APK 的原生映射 | 运动世界快照可见 `dev.posedmcp-…/base.apk`；测试应用稳定快照有 4 条该 APK 映射。 | 进程仍映射模块代码，Java 返回视图不等于原生层移除。 |
| 映射名未必包含 so 文件名 | 测试应用这 4 条映射的起始文件偏移为 `0x12b8000`；当前 APK 内未压缩的 `lib/arm64-v8a/libposednative.so` 数据偏移也是 `0x12b8000`。 | 从 APK 直接加载的库可以只显示为 `base.apk`，仅查找 `libposednative.so` 字符串不足。此数值只适用于本次构建。 |
| 原生读取与 Java 读取不同 | 同一测试应用内 BufferedReader 的模块相关计数为 0，JNI `fopen/fread` 为 21；真实创建的 `memfd:XposedBridge.jar` 映射分别为 0 和 1。 | 已有真实阳性控制，原生直接读取 maps 内容确实仍能得到隐藏标记。测试 JAR 映射是控制例，不是断言框架本身加载了该 JAR。 |
| native 文件开关的含义 | 测试应用报告 native 文件策略 installed=10、failed=0，且目录探测有命中；上述原生 maps 标记仍存在。 | 这些入口过滤选定目录探测，不过滤 maps 的读取内容。开启开关不能视作覆盖原生 maps。 |

本轮稳定测试应用快照未在匹配的 fd 链接、Linux task comm 或筛选的 mountinfo 中发现所查关键词。
这是有限快照的阴性结果；没有覆盖 Java Thread 名、全部时序、JNI、直接系统调用、linker 枚举或内存扫描，不能据此宣称这些面全部隐藏。

测试应用作用域只包含 PosEdMCP。其普通文件、真实 framework.jar、自身堆栈与普通 reader 对照保持正常；
扩展 Java 名单仍仅包含两款目标，所以没有为此次测试改变用户的名单或开关。

## 两款应用的退出与其他模块

LSPosed 配置及实际加载日志均显示，中国移动和运动世界同时加载了启用的
`com.lenerd46.spotifyplus`（auto_include=1）与 PosEdMCP；两者快照中也可见该其他模块的 APK 路径。
因此当前环境不是只加载 PosEdMCP 的隔离对照，不能把退出单独归因于本模块，也不能认定其他模块就是原因。

- 中国移动 12.5.5：短间隔采到 16 份快照，包含主进程与短命子进程；仍记录原生 SIGSEGV，地址 `0x88c` / `0x79c`，退出信息随后为 SIGNALED 9。
  没有采到明确命名的 PosEdMCP 映射或其策略安装日志；框架加载与模块桥接连接已出现，不能将采样阴性解释为从未注入或隐藏成功。
- 运动世界 7.3.93：采到 15 份快照，Java 隐藏安装日志为 0 failed，仍 EXIT_SELF 28。
  早期 CoreComponentFactory 缺失日志发生在策略安装日志之前；未再出现中间构建由单参数 Class.forName 拦截引入的 WorkManagerInitializer 故障。
- 所采状态中的 TracerPid 为 0；没有伪造该字段。没有获得能确定当前退出检测分支的新 tombstone。

本轮没有追加全局 libc 读取钩子：之前确认的原函数跳板 CFI/递归问题仍未解决。
已有中国移动 native 兼容例外及精确包名实验范围保留。后续定位需区分原生读取内容、模块加载时序和多模块环境，
再以关闭基线与普通读取对照验证，不能只通过增加隐藏字符串声称修复退出。
